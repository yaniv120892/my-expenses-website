# Decisions

One line per decision that is hard to reverse, with the reason. The linked doc holds the detail;
load it before changing that area.

| Topic               | Decision                                                                                                                                                                                                                                  | Why                                                                                                                   |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| App shape           | One Next.js App Router app serves the UI and the API. `excel-extraction-service` stays a separate service, reached over HTTP with async webhook callbacks. → [docs/import-lifecycle.md](docs/import-lifecycle.md)                         | One deployment and one codebase for UI and API.                                                                       |
| Network clients     | Every external client is built through `lazy()` and reads env inside its factory.                                                                                                                                                         | A missing env var fails the call, never the import.                                                                   |
| Households          | Data belongs to a household, not a user. The actor's household and role are loaded from the user's row on every request, and the default Prisma client throws on an unscoped query. → [docs/households.md](docs/households.md)            | A role change or removal applies at once; a query that forgets the household fails instead of reading another's rows. |
| Membership          | A member joins only by redeeming a single-use invite that grants `EDITOR` or `VIEWER`, never `OWNER`; joining merges nothing. → [docs/household-membership.md](docs/household-membership.md)                                              | A household keeps exactly one owner.                                                                                  |
| Attribution         | `createdById`/`updatedById` are stamped by a Prisma extension from the request's actor; each member-visible change is recorded in `HouseholdActivity` in the same transaction. → [docs/household-activity.md](docs/household-activity.md) | No write path can skip attribution, and a change and its record commit together.                                      |
| Sessions            | JWT in an httpOnly cookie, backed by a Redis session key and `User.tokenVersion`. → [docs/auth-and-api-tokens.md](docs/auth-and-api-tokens.md)                                                                                            | Logout deletes the key; bumping the version refuses every session at once.                                            |
| API tokens          | `mxk_…` bearer tokens, stored as a hash, HMAC-signed with `JWT_SECRET`, each scope a whole capability. → [docs/auth-and-api-tokens.md](docs/auth-and-api-tokens.md)                                                                       | A forged token is refused before any database lookup.                                                                 |
| Personal agent      | An agent reaches the app only through the stateless `/api/mcp`, with an `AGENT` token; its tools are adapters over the existing services. → [docs/personal-agent-mcp.md](docs/personal-agent-mcp.md)                                      | Agent writes obey the same rules as the web UI's.                                                                     |
| Money               | `Transaction.value` is always ILS; the original currency and amount ride beside it. No 1:1 fallback when a rate is missing. → [docs/money-and-currency.md](docs/money-and-currency.md)                                                    | No total ever adds two currencies.                                                                                    |
| Categorization      | A user's own description mapping first, then AI. Only the category decision may leave the `AI_PROVIDER` model, via `AI_CATEGORY_SUGGESTER`. → [docs/ai-categorization.md](docs/ai-categorization.md)                                      | The flag changes the model, never the question or the record.                                                         |
| Per-row model calls | Bounded by `AI_REQUEST_LIMITS`, never an SDK default. → [docs/ai-categorization.md](docs/ai-categorization.md)                                                                                                                            | They run one row at a time inside a batch request.                                                                    |
| Import matching     | ±5 days and a relative value tolerance; a single normalized-equal description wins without a model call. → [docs/import-matching.md](docs/import-matching.md)                                                                             | A card dates by settlement and a flat tolerance does not scale; the short-circuit keeps a backfill affordable.        |
| Merge-vs-create     | `importService.toReconciliationPlanItem` decides MERGE/CREATE for the preview and every commit path. → [docs/import-matching.md](docs/import-matching.md)                                                                                 | The preview and the commit cannot disagree.                                                                           |
| Duplicate imports   | Card + payment month is the duplicate key; a duplicate becomes a `MERGED` pointer to the oldest COMPLETED import. → [docs/import-lifecycle.md](docs/import-lifecycle.md)                                                                  | A client follows the pointer instead of reconstructing the survivor from the filename.                                |
| Failed imports      | A FAILED import keeps its extraction claim; recovery is delete and re-import. → [docs/import-lifecycle.md](docs/import-lifecycle.md)                                                                                                      | A redelivery after a partial write would insert every row again.                                                      |
| Storage keys        | An S3 key is a random id plus the extension, never the file name. → [docs/uploads-and-storage.md](docs/uploads-and-storage.md)                                                                                                            | A key is logged and travels in URLs.                                                                                  |
| Upload size         | One cap, `src/shared/uploadLimits.ts`, checked by every upload path. → [docs/uploads-and-storage.md](docs/uploads-and-storage.md)                                                                                                         | It sits under a function's request-body limit.                                                                        |
| Telegram linking    | A chat is linked only by the bot hearing `/start <code>` from it; no request names a chat id. → [docs/telegram.md](docs/telegram.md)                                                                                                      | No request can point a user's notifications at a chat they do not hold.                                               |
| Database            | Neon Postgres through Prisma and `@prisma/adapter-pg`, a pool of one with unnamed statements; pooled `DATABASE_URL`, direct `DIRECT_URL`. → [docs/database.md](docs/database.md)                                                          | Unnamed statements are safe in a pooler's reused sessions.                                                            |
| Encryption at rest  | `Import.creditCardLastFourDigits` is encrypted with a random IV and matched in memory. → [docs/database.md](docs/database.md)                                                                                                             | Card digits are sensitive.                                                                                            |
| Redis               | Every key is namespaced by `redisKeyPrefix`; only production is bare. → [docs/redis.md](docs/redis.md)                                                                                                                                    | Previews share production's one Upstash database.                                                                     |
| Region              | Functions run in `fra1`. → [docs/deployment.md](docs/deployment.md)                                                                                                                                                                       | Co-located with Neon and Upstash, so each query and session read is a same-region round trip.                         |
| Site origin         | `requireSiteUrl()`; `WEBSITE_URL` is set on production only. → [docs/deployment.md](docs/deployment.md)                                                                                                                                   | Previews derive their origin; production fails loudly when the value is missing.                                      |
| Liveness            | `/api/health` touches no dependency. → [docs/api-routes.md](docs/api-routes.md)                                                                                                                                                           | Neon can scale to zero.                                                                                               |
| Observability       | The shared `@yaniv120892/observability` package; Sentry gets errors only and no identifying request data. → [docs/observability.md](docs/observability.md)                                                                                | A caught error reported via `reportError` outlives Better Stack's retention.                                          |
| Product events      | PostHog, server-side only, after the action succeeded, with fixed-label properties. → [docs/observability.md](docs/observability.md)                                                                                                      | An event records only what happened, and carries no personal data.                                                    |
| UI                  | `@yaniv120892/my-ui` for theme, shell and i18n; Hebrew by default, English beside it, RTL. → [docs/ui.md](docs/ui.md)                                                                                                                     | Same look and behaviour as My Investments and My Shopping.                                                            |
| Dependency updates  | Dependabot is the only updater; a patch/minor PR auto-merges on green CI. → [docs/dependency-updates.md](docs/dependency-updates.md)                                                                                                      | Routine bumps land without a human; anything riskier waits for one.                                                   |
| Shared tooling      | ESLint, Prettier, tsconfig, lint-staged and the CI `checks` job come from `@yaniv120892/dev-config`, pinned by tag.                                                                                                                       | One config across the sibling repos.                                                                                  |
| Vendored skills     | `pr-review`, `prune-comments` and `steward` are vendored; other workflow skills come from the `claude-config` plugins. → [docs/claude-tooling.md](docs/claude-tooling.md)                                                                 | Sessions here have no `gh` CLI, and remote sessions read `steward` from the head branch.                              |
| Docs                | `DECISIONS.md` plus one short topic doc per area; no specs or plans are committed.                                                                                                                                                        | A spec for shipped work drifts and reads as current intent.                                                           |
